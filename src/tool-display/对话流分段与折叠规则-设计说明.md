# 对话流 Tool 分段与折叠 · 交互标准设计说明

> 规则名：**结构优先分段 + 风险破出**（structure-first segmentation + risk breakout）
> 适用：Web 端通用 Agent 对话流中，assistant 一轮内多次 tool 调用的分组、折叠与展开。
> 目标：折叠行为**对模型叙述节奏免疫**，且**高风险/决策/错误项永不被静默折叠**。

---

## 0. 一句话模型

分段与折叠是**两个正交的决定**，不要混为一谈：

| 决定 | 问题 | 由什么驱动 |
|---|---|---|
| **分段**（segmentation） | 组在哪切、要不要成组 | 结构信号为主、文本为辅（§2） |
| **破出/折叠授权**（prominence） | 某一项能不能被折叠收走 | 风险/副作用等级，正交否决层（§3） |

> 风险**不决定"要不要建组"**，只决定"这一项能不能被藏"。低风险也可能因意图阶段切换而分段；高风险即使落在连续段正中间也必须破出。

---

## 1. 数据前提与字段依赖

聚合后的对话流条目 `Item`：

```
Item = { key, kind: 'tool'|'text'|'thinking'|'turn'|'user', ... }
ToolItem = { kind:'tool', toolUseId, toolName, toolStatus, inputJson, result }
  toolStatus ∈ { running, done, error, interrupted }
```

规则用到的派生/依赖字段：

| 字段 | 来源 | 用途 | 现状 |
|---|---|---|---|
| `toolName` | 已有 | 推断 `template` / `actionClass` | ✅ 前端本地推断（开放集合） |
| `toolStatus` | 已有 | 状态汇总、错误定位 | ✅ |
| `inputJson.command` 等 | 已有 | detail 摘要、命令级风险兜底嗅探 | ✅ |
| **`readOnlyHint` / `destructiveHint` / `idempotentHint`** | **建议工程补** | 风险分级的**可靠来源**（对齐 MCP 注解） | ⚠️ 缺；暂用命令正则兜底 |
| **`stepGroupId`（或 assistant message 边界）** | **建议工程补** | 确定性分段，彻底摆脱节奏猜测 | ⚠️ 缺；暂用文本实质度代理 |

> **关键请求**：`destructiveHint`/`readOnlyHint` 与 message 边界这两个字段，应补进"前端展示字段清单"。前者喂风险破出，后者喂分段，且都可复用给"执行前确认"UI。

## 2. 结构优先分段

### 2.1 动作大类 `actionClass`

按数据形态归三类（跨类跃迁 = 意图阶段切换 = 分段边界）：

| 类 | 含 template | 语义 |
|---|---|---|
| `explore` | read, search | 查（收集上下文） |
| `mutate` | edit, todo | 改（写工作区） |
| `act` | exec, web, struct, fallback | 执行 / 对外 |

### 2.2 文本按"实质"计权，而非"有无"

`isFillerText(item)` 判定为**引子**（不作硬分隔）：

- 显式 `lead` 标记；或
- 长度 ≤ 18 字；或
- 以引导词开头：`先 / 再 / 然后 / 接着 / 接下来 / 下面 / 首先 / 顺手 / 现在…`

> 实质性叙述（结论、段落）与 `turn` 才是**硬分隔**。引子在结构视图里可标灰保留（"💬 …（已忽略）"），但不参与分段。

### 2.3 分段边界（满足任一即切）

1. 遇到**实质文本 / turn** → 冲刷当前组；
2. 遇到**破出项**（§3.1）→ 冲刷 + 该项独立成卡；
3. **动作大类跃迁**（相邻 tool 的 `actionClass` 不同）→ 冲刷；
4. **尺寸上限** `SIZE_CAP`（默认 6）→ 冲刷，防止巨组糊成一堵墙。

连续且未被上述打断的 tool 归一组；**组内 ≥2 折叠，=1 原样单卡展开**。

### 2.4 伪代码（与原型 `segmentByStructure` 一致）

```
buf = []
for it in items:
  if it is not tool:
    if isFillerText(it): emit filler(it); continue      # 忽略为分隔
    flush(); emit stream(it); continue                  # 实质文本 = 硬分隔
  if isBreakout(it): flush(); emit break(it); continue  # 破出
  if buf 非空 and (class(last) != class(it) or len(buf) >= SIZE_CAP): flush()
  buf.push(it)
flush()
# flush: len>=2 → group ; len==1 → single
```

## 3. 风险破出（正交否决层）

### 3.1 显著度档位 `surfacePolicy(item) → break | pin | surface | group`

| 档位 | 适用 | 行为 |
|---|---|---|
| **break**（破组） | 副作用/不可逆/对外（`destructiveHint` 或命令嗅到 `git push`/`rm -rf`/`deploy`/`kubectl`/`curl -X POST\|DELETE`…）；决策类 `AskUserQuestion`；子 Agent `Task` | 截断连续段，独立成卡，完整可审计。截图里的 `git push` 即此档 |
| **pin**（组内钉住） | 用户点名要看的产物 / 长结果 | 组不拆，但该项在组内**默认展开且不可被折叠收走**，标题标注 |
| **surface**（仅标题提示） | 组内含 `error`，或组内有单个写操作但整体仍为查/改阶段 | 仍折叠，但汇总标题**点名**（"执行 3 次命令（含 1 次 `git push`）· ⚠ 1 失败"），展开时该子项**自动 expand 并滚动定位** |
| **group** | 其余只读/幂等 | 正常折叠 |

> 硬约束：**`error` 与破坏性操作绝不允许被静默折叠**。要么 break，要么 surface（标题点名 + 展开自动定位）。埋一个 `git push` 进"执行 N 次命令"是设计事故。

### 3.2 风险判定优先级

1. `destructiveHint === true` → break（首选，来源可靠）；
2. 无注解时，对 `Bash.command` 正则兜底嗅探危险模式 → break；
3. `template === 'ask'` 或 `Task` → break（决策/子流程）；
4. 其余 → group。

> 现状原型：已实现 §3.1 的 **break**（`isBreakout`），pin / surface 为提案（标注实现状态）。

## 4. 折叠卡展示标准

### 4.1 动态标题（按动作桶计数）

- 格式：`<动词> N <量词> · …` 按桶拼接，例：**"浏览 2 个文件 · 编辑 3 个文件 · 执行 1 次命令"**。
- 不宣称"相关"，只客观汇总"哪几类、各几次"——异构组也因此可读。
- 若组内有 surface 项，标题追加点名段（§3.1）。

### 4.2 状态汇总（rollup）

优先级 `running > error > interrupted > done`；组卡边框/圆点取该态色。

### 4.3 默认展开策略

| 情形 | 默认 |
|---|---|
| 组内含 `running` | **展开**（进行中要可见） |
| 组内含 `error`（且未 break） | **展开**，并定位到错误子项 |
| 纯 done 组 | **收起** |
| 单卡（single） | 按模板既有规则（edit/todo/ask 默认展开，结果承载默认收起） |

### 4.4 计数与右信息区

组卡右侧显示 `N 步`；子卡右侧沿用既有（diffstat / 计时 / 行数）。

## 5. 交互细则

- **展开/收起**：整条 head 可点；`running` 组自动展开且完成后不强制收起（尊重用户当前展开态）。
- **错误定位**：展开含错误的组时，错误子项自动 expand 并进入视口。
- **结果卡动作**（done 且非 ask/todo）：`复制` / `原始 ⇄ 格式化` / `打开文件`（read/edit，点路径标记 ↗）。
- **子 Agent（Task）**：常驻进度行（`最近调用 · 步数 · 时长 · summary`），可展开子对话流（子流程内递归套用本规则）。
- **铅笔模式（web-next 现状）**：不折叠、平铺弱化行；本规则仅作用于卡片模式。

---

## 6. 边界与降级

| 场景 | 处理 |
|---|---|
| 空组 / 单项 | 不折叠，原样单卡 |
| 超大组（≥ SIZE_CAP） | 按动作大类切子段；仍超限则按 SIZE_CAP 硬切 |
| 未知 `toolName` | `actionClass` 兜底为 `act`；`fallback` 模板显示原 name |
| 无 `destructiveHint` | 降级到命令正则嗅探；嗅不到则按 group（**宁可少破、不可误藏**？见风险取向） |
| 空结果（如 grep 无匹配） | 视为**成功空态**，不报错 |

> **风险取向决策点**：无注解且嗅探不确定时，选"宁可多破出（安全，略碎）"还是"宁可少破出（干净，略险）"，需产品拍板。建议对 `Bash` 默认偏保守（多破）。

---

## 7. 可配置项与默认值

| 参数 | 默认 | 说明 |
|---|---|---|
| `SIZE_CAP` | 6 | 单组最大 tool 数 |
| `FILLER_MAX_LEN` | 18 | 引子文本长度阈值 |
| `GROUP_MIN` | 2 | 成组最小连续 tool 数 |
| `segmentBoundaryOnClassChange` | true | 动作大类跃迁是否切段 |
| `riskFallbackMode` | `aggressive` | 无注解时 Bash 危险嗅探的松紧 |

## 8. 验收标准（黄金用例）

以"查 3 → 改 3 → 测 1 → 推送 1（推送高危）"为基准，两种模型节奏喂入：

| 输入 | 纯文本规则（对照） | **结构优先 + 破出（应达）** |
|---|---|---|
| 惜字模型（无插话） | 1 组 8 步全糊，push 被埋 ❌ | 2 组 + 1 单卡 + **push 破出** ✅ |
| 话痨模型（每步引子） | 8 张单卡全平铺 ❌ | 2 组 + 1 单卡 + **push 破出** ✅ |

**核心验收**：结构优先规则下，**两行输出必须一致**（对模型啰嗦程度免疫）；且 `git push` 在任一节奏下都独立成卡、绝不进组。
